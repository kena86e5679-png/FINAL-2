# click clip!!（v6）

手機 AR 虛實整合對戰。手機鏡頭是玩家的代理人：先判讀真實空間、用符號界定場地，再在真實空間上生成虛擬建築，2～8 人對戰。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html` | 手機遊戲（封面 click clip!!、進房、拍照建檔、範圍設定、校正、對戰、結算） |
| `game.js` | 遊戲流程與畫面 |
| `engine.js` | AR 引擎：感測器、地圖座標、視野限制、建築繪製、牆面偵測（由 v5 `app.js` 移植） |
| `vision.js` | 人物骨架（MoveNet）、外觀辨識、符號偵測、光流（前進／後退／左右） |
| `room.js` | 房間規則（伺服器與手機主機共用）：編號、範圍、命中判定、建築生成 |
| `net.js` | 連線：Node 伺服器（WebSocket）或 GitHub Pages 模式（PeerJS） |
| `server.js`、`package.json` | Node 伺服器（可選） |
| `dashboard.html` | 地圖監控端 |
| `trainer.html`、`trainer.js` | 空間判讀訓練工作台（已修好 API 連線） |
| `symbol-print.html`、`symbol.svg` | 列印符號 |

舊的 `app.js` 已不再使用，可以刪除。

## 放上 GitHub Pages（不用伺服器）

1. 把上表所有檔案上傳到 repository 根目錄。
2. 手機開 `https://你的帳號.github.io/你的專案/`。
3. **第一個進房的裝置會變成「房間主機」**，房間規則在它上面執行；它的畫面要一直開著（螢幕關掉房間會暫停）。比較穩的做法：先用電腦開 `dashboard.html` 輸入房號連線，讓電腦當主機，玩家再用手機進房。
4. 玩家最好在同一個 Wi-Fi。PeerJS 走 WebRTC，部分行動網路／公司網路會連不上。

## 用 Node 伺服器（比較穩）

```
npm install
npm start          # http://localhost:3000
```

- iPhone 必須用 https：`cloudflared tunnel --url http://localhost:3000`，或部署到雲端主機（Render、Railway 等）。
- GitHub Pages 的網頁也可以連你的伺服器：網址加 `?server=wss://你的伺服器網址`。
- 訓練工作台的 Gemini Key 可放在伺服器環境變數 `GEMINI_API_KEY`，工作台選「後端 Server 代理」。

## 遊戲流程

1. **進房**：輸入暱稱與房號，系統隨機給你 A～Z 其中一個字母。
2. **拍照建檔**：鏡頭對準其他玩家按快門，再選他的字母。系統用骨架找出頭髮、上衣、褲子區域，記下顏色分布、肩寬/軀幹比例（胖瘦）與身高。每人至少要被拍一次。
3. **範圍設定**：伺服器隨機抽兩人。
   - S1 的人把符號放在場地一角、站上去；（建議）面向一條邊（沿牆）按「設定邊方向」。
   - S2 的人把符號放在對角、站上去。
   - S1 的人把準心對準 S2 的人的腳（或 S2 符號）按「測量對角線」。
   - 距離 = 眼高 ÷ tan(俯角)。對角線加上邊方向，用畢氏定理算出矩形 W × D（W² + D² = 對角線²）。沒指定邊方向時視為正方形。
   - 兩人按下站上符號時也會記錄 GPS；室內 GPS 誤差通常 5～30 m，誤差超過 12 m 不採用。量不到時可手動輸入尺寸。
4. **站位校正**：每個人站上 S1 或 S2，準心對準另一個符號按「對準」。系統由此得知你的位置與面向，並依據對角線長度微調眼睛高度。
5. **對戰**：每人 10 條命。中央十字準心對準敵人、點螢幕攻擊。
   - 判定由手機方位（陀螺儀）＋伺服器上的座標＋鏡頭裡看到的人（骨架＋外觀比對）共同決定，伺服器再複核角度、距離與虛擬牆遮擋。
   - 敵人以白色虛線框＋淡紅濾鏡標示，被虛擬建築擋住時不顯示。
6. **點陣座標**：場地內每 1 m 一個點，畫在地上。走到點上按「定位」，後台記錄你的位置，監控端會亮起該點。
7. **校正誤差**：準心掃過地上的實體符號時，系統用符號位置修正你的座標。點陣是虛擬的，無法修正誤差；能修正的只有現實中的東西，所以多放幾張符號（「新增符號錨點」）會更準。
8. **移動判斷**：計步器偵測每一步，光流判斷方向：畫面放大＝前進、縮小（zoom out）＝後退、整體橫移＝左右平移（會先扣掉手機轉動造成的移動）。
9. **空間同步**：鏡頭偵測到的牆、柱、陰角／陽角，以及 COCO-SSD 認出的桌椅，都會回報伺服器，標在監控地圖上。
10. **建築生成**（伺服器決定，所有人看到同一份）：
    - 每個候選點向 16 個方向量出空曠距離。
    - 平均空曠度 ≥ 2 m、最近障礙 ≥ 0.9 m、附近物件不超過 2 個才生成；越空曠生成越大的構件（L 型牆 → 牆 → 柱 → 胸牆掩體）。
    - 不會長在真實牆／桌椅上。
    - 與玩家保持 1.5 m 以上，建築之間保留 0.9 m 通道。
    - 數量依場地面積決定。

## 測試（電腦瀏覽器）

- 網址加 `?debug=1` 會顯示除錯資訊。
- 沒有感測器時：拖曳畫面轉向，WASD 移動，空白鍵開火。

## 已知限制

- 所有距離來自單眼推算（眼高＋俯角）。手機拿高或拿低都有影響，校正後通常誤差 10～20%。
- 陀螺儀方向會慢慢漂移，玩久了請回符號「重新校正」。室內羅盤受鋼筋干擾，所以方向以符號校正為主，不依賴羅盤。
- 人物辨識靠衣著顏色和體型。兩人穿得很像、背光、太遠（8 m 以上）或只露半身時容易認錯；認不出時改用座標判定。
- 主機模式下，主機斷線房間就會結束。
- 這版沒有在 iPhone 實機上測過，只用電腦瀏覽器加模擬鏡頭、模擬多人測試。
